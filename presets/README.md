# Предустановки карточек

11 JSON-шаблонов schema_version=1 поставляются с приложением и устанавливаются активными при первом запуске версии 0.3.1. Ручная загрузка ZIP/JSON не требуется. Основа — анализ 1685 однозначно опубликованных карточек; личные карточки, PN, GTIN и документы в репозиторий не включены.

Автоматически дозаполняются только пустые поля:

- 3959 — первые четыре цифры выбранного полного ТН ВЭД;
- 13933 — полный ТН ВЭД соответствующего профиля;
- 3961 — самый частый ОКПД2 опубликованной выборки по ТН ВЭД, по прямому указанию владельца. Сотрудник может изменить его вручную.

Заполненные поля сохраняются. Для встроенных профилей недостающие три поля могут быть добавлены локально. Сопоставление характеристики выполняется по официальному ID, категории — по проверенным названиям/ID из снимка НК и полному ТН ВЭД. Наборы и комплекты не преобразуются в единичные товары. Произвольная категория не считается подтверждённой только из-за совпадения ТН ВЭД.

В интерфейсе: «Шаблоны» → «Создать карточку по шаблону» либо выбрать существующие карточки в реестре → «Применить шаблоны» → проверить и подтвердить план. PN, наименование, бренд и индивидуальные характеристики заполняются для конкретного товара; режимы required_input/suggest_only описывают правила, но не подменяют проверку схемы НК.

Установка не создаёт товарных карточек, не ставит внешние операции в очередь и не обращается к НК. Повторный запуск не создаёт дубликаты шаблонов и не отменяет выбор своей активной версии.

При обновлении пустой PN у чистой локальной копии восстанавливается из официального атрибута 13914 сохранённого снимка НК. При нескольких значениях отбрасывается совпадающее с брендом; если остаются разные артикулы, автоматического выбора нет. Локальные правки, уже заполненные PN и карточки с незавершёнными внешними заданиями не меняются.

`manifest.json` содержит области применения и агрегированное происхождение. JSON-файлы по одному можно использовать как обычные предложения, но при обновлении они уже установлены автоматически.
