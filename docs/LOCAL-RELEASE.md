# Рабочий локальный выпуск 0.2.0

Цель: позволить владельцу запустить настоящий сервис в WSL2, проверить интерфейс на своих данных и выгрузить корпус для шаблонов. Это частичная реализация исходного большого ТЗ, не завершение полного цикла НК.

## Реализовано

FastAPI, SQLite WAL, постоянные карточки/снимки/атрибуты, ревизии и ответственные; серверные сессии и отдельный админский пароль, CSRF/Origin и rate limit входа; XLSX с сохранением файла и исходных строк, mapping и явными общими значениями; сравнение PN/GTIN с причиной; история и локальный архив; JSON/XLSX/ZIP без секретов; локальные шаблоны, версии, approval, preview и применение только в пустые поля; backup/restore в новый файл, версия и asset hash; loopback-launcher WSL2 с проверкой свободного порта.

Схема БД — версия 1, создаётся идемпотентно. Производственных endpoint НК в коде нет, placeholder-методы возвращают явную недоступность и не делают внешних вызовов.

## Проверено

Пройдены **14 автоматических API/интеграционных тестов**: пустая база и рестарт; права и CSRF; сохранение неудачных попыток входа; настоящий XLSX и идемпотентность; конфликт локальных правок; формулы/GTIN; повтор ID внутри файла; ревизии/совпадения; утверждение и fill-if-empty; неизвестные/индивидуальные поля; ZIP hashes и защита XLSX от формул; backup и очистка сессий; архив; явные общие значения; сохранение настоящего внешнего ID при обновлении снимка.

Пройдены **8 групп browser smoke** через штатный `scripts/run_wsl.py`, получены 7 скриншотов. Проверяется фактический HTTP/SQLite workflow, XLSX, редактирование, экспорт, админский вход и локальный цикл шаблона. Результат: `live-browser-report.json`, скриншоты `screenshots/live-*.png`. Входные данные тестов синтетические и существуют только в изолированном временном каталоге; деморежима в приложении нет.

## Не проверено

Конкретный Windows/WSL2 пользователя, проброс localhost, реальная форма корпоративного полного XLSX НК, объём и имена его колонок. Прямой API НК, права компании, текущие схемы, производственные подписи/мутации не проверялись. После получения первых настоящих файлов нужно уточнить автоматическое сопоставление по фактическим заголовкам.

## Ограничения и следующие работы

- Нет прямой синхронизации НК, выдачи GTIN, модерации, аппаратной подписи, публикации и внешней долговечной очереди. Снимок статуса XLSX не считается свежим фактом API.
- Типы характеристик пока текстовые; имена — исходные колонки. Локально активный шаблон не равен проверенной схеме НК.
- Для повторной связи источника используется настоящий ID, если он есть. Если в XLSX нет ID — отдельный внутренний ключ источника по GTIN. Этот ключ **не подставляется** в поле внешнего ID НК. Совпадающие исходные ключи внутри файла дают конфликт.
- Смена схемы идентификации файла (в прошлом без ID, теперь с другим ID) требует разбора: автоматически объединять неизвестные внешние экземпляры опасно.
- Уже принятый файл нельзя повторно импортировать по тому же SHA-256. Для оставшихся после частичного успеха строк нужен исправленный файл; готовые записи не создаются заново молча.
- Каталог загружается в браузер целиком; локальная пагинация и фильтры подходят для первичного пилота, серверная пагинация больших каталогов остаётся дальнейшей работой.
- В отфильтрованном экспорте список ID ограничен длиной URL; для большого корпуса есть отдельная выгрузка всех записей в «Шаблонах».
- Сохранённые схемы mapping пользователя, массовый архив, расширенные отчёты ошибок XLSX, сложные справочники, загрузка фото/документов и автоматический планировщик backup пока отсутствуют.
- Экспортная таблица содержит до 230 характеристик и стандартные поля; JSON хранит все. Проверяйте коммерческие данные перед передачей внешнему агенту.

После локального UI-пилота: получить реальную выгрузку, подготовить шаблоны категорий, подключить подтверждённый read-only API и официальные схемы. Внешние необратимые действия — отдельный согласованный пилот, а не скрытый эффект импорта.
