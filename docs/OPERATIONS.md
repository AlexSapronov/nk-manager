# Локальные операции выпуска 0.2.0

Создание карточки, редактирование, подтверждение дубля, импорт и применение шаблона меняют только SQLite. Каждая запись истории содержит пользователя и время; у правок/планов есть ревизии. Импорт выполняется в транзакции с результатами каждой строки; успешное подтверждение плана повторно возвращает сохранённый результат, а не создаёт новые карточки.

Внешняя очередь хранится в SQLite. Команды требуют явного подтверждения и проверки ревизии/ответственного. Перед запросом намерение отправки фиксируется как dispatching; после сбоя такой результат становится unknown и не отправляется повторно. Квитанции и снимки неизменяемы. Подробности сверки — в [NK-LIVE.md](NK-LIVE.md).

Архив — локальная отметка. Подготовленные задания отменяются; уже отправленные продолжают проверяться. Локальное редактирование блокируется на время внешней операции. Внешний архив НК этим действием не меняется.

Рабочая БД, исходные XLSX, шаблоны и аудит находятся в одном файле SQLite с WAL. Не копируйте только основной sqlite3-файл работающего сервиса обычным `cp`: используйте SQLite Backup API в `scripts/backup.py`. Проверяется integrity/foreign keys; старые сессии из снимка удаляются. Восстановление только в новый путь, со штатно остановленным сервисом. Команды — в `WSL.md`.

Сервис не удаляет карточки, исходные файлы, планы или backup автоматически. Наблюдайте свободное место; лимит входного XLSX 20 МБ, распакованного содержания — 80 МБ, до 20 000 строк / 250 колонок. Пробные повторные preview сохраняются в базе, поэтому для больших импортов не нажимайте пересчёт без необходимости. Очистка старых preview потребует отдельной явной административной функции.
