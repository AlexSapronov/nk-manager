Автоматизированные сценарии: загрузка реестра, поиск, панели и вкладки, редактирование и сохранение макета, переход следующая, выбор между страницами, preview шаблона, причина PN, четыре шага импорта, diff, партии/unknown, видимость админки, пустой каталог, offline/conflict, screenshot на четырёх размерах и 125% через CSS viewport emulation. Ручное согласование: открыть `prototype/preview.html`, пройти README, утвердить или исправить структуру. Все будущие рабочие механизмы остаются непроверенными.

## Полная приёмка после этапов 2–6

36 исходных сценариев сохраняются в `TASK.md`, раздел 19. На следующих этапах каждый получает ссылку на тест или ручное доказательство, а не общий статус «готово».

Ключевые обязательные доказательства:

- read-only импорт повторяется без новых ID; опубликованная/черновая версии — один товар;
- шаблон не перезаписывает значения, не переносит уникальные поля и не действует вне категории;
- Excel сохраняет исходные строки/идентификаторы, повторный файл не создаёт карточки молча;
- точный и близкий PN дают объяснение и разрешаемое аудируемое предупреждение;
- сотрудник может публиковать, но не менять конфигурацию/активировать шаблон через прямой API;
- stale revision не перезаписывает актуальную; таймаут мутации → unknown без повторной выдачи GTIN;
- остановка не обещает отмену НК; возврат не запускает очередь без сверки;
- backup восстановлен в изолированном пути без внешней отправки;
- после обновления проверены service, commit SHA, assets и smoke.

## Реальный пилот — только после отдельного разрешения

1. Согласовать точные данные и неизменяемые поля одного нового товара; проверить права GTIN и дубли.
2. Получить разрешение на перечисленные внешние действия и подпись УКЭП.
3. Пройти маршрут до подтверждённого опубликованного статуса НК с квитанциями.
4. Дозаполнить отдельный существующий черновик, доказать сохранение его внешнего ID.
5. Выполнить небольшую согласованную партию; проверить частичные результаты и повторный запуск.
6. Проверить реальную Windows-подпись без административных прав и документировать PIN/политики.

Если API-этап недоступен, фиксировать ограничение. Наличие кнопки или HTTP 200 не закрывает сценарий.
