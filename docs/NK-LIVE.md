# НК: API и подпись в Windows

Версия 0.3.0. Прямой клиент российского НК реализован по официальной документации v5.68 от 28.09.2026. В рабочем приложении нет подставных ответов. Автотесты изолированы и используют синтетический транспорт; реальные права организации, ключ и аппаратная УКЭП здесь не проверялись.

## Обновление существующей установки Alex

Остановите сервис через Ctrl+C. База и настроенный пользователь `alex` сохраняются; повторять setup не нужно. Сначала сохраните копию `data` при остановленном сервисе. Не удаляйте `.venv` или SQLite ради обновления. При локальных изменениях `git switch` может остановиться: сохраните их отдельно, не применяйте reset --hard.

В Ubuntu 24.04 / WSL2:

```bash
cd ~/nk-manager
sudo apt update && sudo apt install -y python3.12-venv
cp -a data "data-before-nk-$(date +%Y%m%d-%H%M%S)"
git fetch origin && git switch codex/nk-live && git pull --ff-only
python3 -m venv .venv && .venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python scripts/run_wsl.py
```

Пакет venv устраняет вашу ошибку `ensurepip`; повторное создание окружения добавляет pip в уже существующую `.venv`. При сбое установки зависимостей не переходите к запуску. Откройте http://localhost:8020 в Windows. На новой установке после установки зависимостей один раз выполните `scripts/setup.py` через `.venv/bin/python`.

## Подключение

Войдите как администратор: ваш username и ранее заданный пароль. В «Администрирование → Подключение Национального каталога»:

1. Выберите промышленный контур, введите API KEY и SHA-1 отпечаток сертификата Windows. Ключ вводится только здесь, не в чате и не в командной строке.
2. Сохраните подключение. «Проверить API» читает список за последние сутки; это проверка доступа, а не полноты каталога.
3. Нажмите «Получить каталог и черновики». Дождитесь `confirmed` в «Партии → Операции НК». Синхронизация включает список с явным диапазоном дат с 2000 года, страницы и полные карточки. При лимите 10000 диапазон делится; неполный ответ не считается успехом.
4. Для отправки разрешите внешние действия в настройках. Каждая команда всё равно требует отдельного подтверждения сотрудника.

Рабочие адреса задаются кодом для production/sandbox, произвольный сервер с вашим ключом не допускается. Смена контура после привязки карточек блокируется: для другого контура используйте отдельный каталог данных. API KEY и токен подписанта хранятся в `data/nk-secrets.json` с правами 0600. Обычная выгрузка каталога и SQLite backup этот файл не включают; храните его резервную копию отдельно и конфиденциально. При полном копировании папки data секрет тоже копируется.

## Подписант Windows — из marking-bm

Нужны установленный CryptoPro CSP, CAdESCOM, драйвер токена и сертификат с закрытым ключом в хранилище текущего пользователя Windows. Подписание выполняет Windows Script Host через `Sign-Payload.vbs`, как в marking-bm. Закрытый ключ и PIN не передаются в WSL.

В Windows PowerShell найдите сертификат:

```powershell
Get-ChildItem Cert:\CurrentUser\My | Where-Object HasPrivateKey | Select-Object Subject,Thumbprint,NotAfter
```

Скопируйте оба скрипта из WSL в Windows:

```powershell
$signerDir = Join-Path $env:USERPROFILE 'nk-signer'
New-Item -ItemType Directory -Force $signerDir | Out-Null
Copy-Item '\\wsl.localhost\Ubuntu-24.04\home\alex\nk-manager\signer\*' $signerDir -Force
Set-Location $signerDir
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Signer.ps1 -Server http://localhost:8020 -Thumbprint ВАШ_ОТПЕЧАТОК -Diagnose
```

`-Diagnose` выполняет локальное создание и проверку attached/detached CAdES, без сети и операций НК. Затем запустите без `-Diagnose`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Signer.ps1 -Server http://localhost:8020 -Thumbprint ВАШ_ОТПЕЧАТОК
```

Для отдельной проверки связи без получения заданий добавьте `-CheckConnection` к команде запуска. Успех: `Connected to signer endpoint`. При ошибке скрипт указывает этап и HTTP-код: 403 — токен/версия сервера, 422 на heartbeat — сохранённый отпечаток сертификата, 404 — адрес/версия сервера. Без HTTP-ответа проверьте доступность адреса из Windows; при проблеме localhost попробуйте 127.0.0.1. Ответы сервера и секреты не печатаются.

В админке нажмите «Показать токен подписанта» и введите именно этот токен в скрытый запрос PowerShell. Это отдельный токен, не API KEY. Окно PowerShell должно оставаться открытым; остановка Ctrl+C. Подписант проверяет тип задания, сертификат, SHA-256 точных байтов XML, формат подписи и локально проверяет CMS. Сервер проверяет аренду задания, контрольную сумму и наличие настроенного сертификата в CMS; окончательную криптографическую проверку ГОСТ выполняет НК.

Если работает подписант marking-bm, остановите его. Новый брокер может последовательно обслуживать оба сервиса:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Signer.ps1 -Server http://localhost:8020 -Thumbprint ВАШ_ОТПЕЧАТОК -MarkingServer http://localhost:8010
```

Адрес marking-bm замените на свой; сертификат должен быть общим. Появятся два запроса отдельных токенов. Не запускайте старый подписант одновременно: он не участвует в mutex нового брокера. В пределах сессии Windows новый брокер защищён от повторного запуска. Для удалённых адресов разрешён только HTTPS.

## Работа с карточкой

Откройте карточку и возьмите её в работу. «Сохранить» сохраняет локальный черновик. Вкладка «НК» содержит отдельные действия:

- Загрузить схему категории по ТН ВЭД. Реальные ID полей сохраняются; доступны текст, числовая проверка, встроенные списки значений и единицы.
- Создать/обновить в НК. Существующая карточка передаётся со своим good_id. Подтверждение требует статуса feed и повторного чтения фактических значений.
- Отправить на модерацию. Подписание доступно, когда НК вернул `notsigned`.
- Подписать и опубликовать. Сервер получает XML НК, Windows подписывает точные байты откреплённой CAdES-BES, сервер отправляет CMS и подтверждает `published` + `good_signed` повторным чтением.
- Получить GTIN — отдельное явно подтверждаемое выделение одного кода для PN без GTIN. Создание карточки само не выделяет код.

Для внешней команды нужна завершённая успешная синхронизация всего каталога; ограничения в 15 минут нет. Если последняя синхронизация ещё идёт или завершилась ошибкой, дождитесь подтверждения или повторите её. Перед изменением существующей карточки сервис заново читает её из НК и проверяет снимок: при внешних изменениях отправка блокируется. Во время активной команды локальное редактирование блокируется. Локальный архив останавливает ещё не отправленные команды; отправленная операция продолжает проверяться. Предыдущие снимки и квитанции сохраняются в SQLite.

`unknown` означает, что внешний запрос мог выполниться, но подтверждения нет. Сервис не повторяет его вслепую. Администратор может выполнить только чтение для сверки результата. Если выделение GTIN закончилось неизвестным результатом, нужно выяснить выделенный код в НК/поддержке; автоматического повторного выделения нет. При изменении карточки в НК локальная версия сохраняется и отправка блокируется до сравнения. Кнопка загрузки актуального снимка требует подтверждения и сохраняет прежний локальный вариант в аудите.

## Границы выпуска

Создание/редактирование реализовано для единичных товаров. Наборы и комплекты можно читать и подписывать после подготовки в НК; редактирование состава и смена типа/категории существующего товара заблокированы. Удаление атрибута, смена закреплённого GTIN/ТН ВЭД и сложные изменения упаковок требуют отдельной реализации. Внешние `preset_url` и зависимые справочники не имеют специального редактора; окончательную проверку значений и прав выполняет НК. Недоступные по правам или статусам карточки делают синхронизацию неполной, а не скрываются как успешно загруженные.

Проверки: Python-тесты контракта/очереди и браузерный цикл с синтетическим НК и программным CMS. Windows CI проверяет синтаксис PowerShell. Это не аппаратный тест CryptoPro/Рутокена и не успешная публикация в вашей организации. Для пилота сначала выполните чтение своим ключом, локальный `-Diagnose`, затем осознанно отправьте одну выбранную карточку и дождитесь подтверждения НК.

## Выгрузка для шаблонов

После подтверждённой синхронизации откройте «Шаблоны → Выгрузить весь каталог для анализа». ZIP содержит JSON со снимками НК, XLSX и манифест. Передайте его в чат для подготовки шаблонов категорий. Можно также передать исходный полный XLSX НК. Ключи и CMS в эту выгрузку не входят.

При проверке дублей учитываются только полные совпадения PN (с учётом регистра и всех внутренних знаков, без пробелов по краям) или GTIN. Похожие PN разных исполнений не требуют обоснования.

### Видимые характеристики

В редакторе по умолчанию показаны характеристики, хотя бы раз заполненные в опубликованных карточках того же ТН ВЭД, и все заполненные значения текущей карточки. Исходный профиль рассчитан по 1 685 опубликованным карточкам; новые заполненные поля добавляются после синхронизации опубликованных товаров. Пустые неиспользуемые поля доступны по кнопке «Показать все поля». Скрытие не удаляет данные и не меняет проверки НК. Если для ТН ВЭД нет опубликованного образца, показываются все характеристики.

### Новая карточка по эталону (0.4.0)

1. Нажмите «Создать карточку». Введите PN, ТН ВЭД и фактический товарный знак (подсказки берутся из опубликованных карточек).
2. Выберите вид товара. Проверьте полное наименование: PN + пробел + выбранный вид.
3. «Заполнить и проверить» открывает локальную подготовку с эталонными общими полями. Проверьте бренд, ОКПД2 и характеристики, затем сохраните.
4. Укажите существующий GTIN либо получите новый на вкладке «НК». Категория и бренд уже сохранены, повторно вводить их в подтверждении отправки не требуется.
5. Создайте карточку в НК, дождитесь подтверждения, затем отправьте на модерацию и подпишите.

Для существующего черновика используйте «Выбрать вид и заполнить по эталону». Уже заполненные общие характеристики сохраняются; выбранные PN/вид/полное наименование согласуются заново. Сохранение в менеджере само по себе не отправляет данные в НК. Старые опубликованные карточки автоматически не переписываются.

Справочник пересобирается воспроизводимо: `.venv/bin/python scripts/build_product_kinds.py ПУТЬ_К_nk-catalog-analysis.zip`. В репозиторий записываются виды/бренды, агрегированные частоты и параметры категорий; индивидуальные PN и GTIN не записываются.

### Ошибка «Значение 8536 атрибута Группа ТНВЭД не найдено»

В версии 0.4.1 исправлена отправка новой карточки: полный десятизначный код передаётся в `tnved`, атрибуты 3959/13933 исключаются из `good_attrs` — их формирует НК. Значения остаются в локальной карточке и шаблонах. Исправление применяется также к ранее сохранённым черновикам при подготовке новой команды.

Если фид получил именно `Rejected`, обновите сервис и повторите «Создать / сохранить в НК» для того же черновика и GTIN. Повторно выделять GTIN не нужно. При статусе «Исход неизвестен» сначала выполните сверку — такую операцию повторять вслепую нельзя.

### Приведение всех черновиков (0.5.0)

В реестре кнопка «Привести все черновики к эталону» анализирует всю локальную базу после синхронизации. Сначала проверьте предпросмотр «было → станет», отметьте нужные карточки и нажмите «Применить локально». Пустые поля заполняются по эталону; PN/вид/наименование согласуются при однозначных исходных данных. Неполные и противоречивые данные показаны отдельно. Точные дубли сохраняются в истории; локальное заполнение не требует причины продолжения.

После применения можно открыть первую карточку для проверки или подготовить отправку карточек без нерешённых вопросов. Перед реальной отправкой сохраняются обычные подтверждение и проверки НК. Уже опубликованные карточки и карточки на модерации не обрабатываются. Текущее наполнение определяется вашей локальной синхронизацией; новая загрузка каталога обновит набор черновиков для следующего прохода.

В версии 0.5.1 фильтр категорий заменён списком с поиском и переносом длинных названий. Он ограничен шириной окна, поддерживает стрелки, Enter и Escape. Выбор сохраняет точное значение категории источника; одинаково выглядящие части разных названий не объединяются автоматически.

### Рабочий процесс черновиков (0.6.0)

Откройте «Черновики». Этапы: «Заполнить» → «Отправить» → «Модерация» → «Подписать». У каждой карточки показаны только недостающие данные и следующее действие. «Заполнить автоматически» сохраняет общие поля без обязательного просмотра технического плана. Оставшиеся PN, ТН ВЭД, бренд и вид указываются в карточке; свободную карточку можно редактировать без отдельного «Взять в работу».

Черновик с полным совпадением PN опубликованного товара по умолчанию скрыт в реестрах и исключён из автоматического заполнения. Переключатель показывает такие карточки и ссылку на опубликованный товар. Регистр и знаки PN учитываются. Карточки не удаляются.

«Отправить на модерацию» — одно подтверждение для сохранения в НК и последующей модерации. Между этапами сервис дожидается подтверждения НК; связь этапов хранится в БД и продолжается после перезапуска. Отклонение/неизвестный исход сохранения не запускают модерацию. Подписание — отдельный шаг после успешной модерации. Состояния обновляются автоматически, пока вы не редактируете карточку.

Локальное сохранение, импорт и дозаполнение больше не блокируются совпадениями и не требуют объяснительных. Совпадения пишутся в историю. Подтверждение реального создания дополнительного товара/GTIN с совпадающим идентификатором остаётся на внешнем действии; повторно при модерации/подписании существующей карточки оно не требуется. Контроль ревизии, чужой занятости, формата идентификаторов и результата НК сохранён.

### Ошибка 404 при отправке существующего черновика

Карточка НК может содержать несколько категорий: классификационную по ТН ВЭД и товарную. Если `/v3/attributes` возвращает 404 для первой категории, менеджер запрашивает схему остальных категорий этой же карточки. Обновление отправляется по прежнему `good_id`; категория, GTIN и сама карточка не пересоздаются. При ошибках доступа, ограничении частоты или сбое сервера подстановка не выполняется. Если ни одна схема не найдена, отправка останавливается с перечнем категорий.

После обновления повторите «Отправить на модерацию» для этих черновиков. Ошибка получения схемы возникает до отправки данных в НК; локальные изменения остаются сохранёнными. Если появится другая ошибка, сообщение укажет метод и адрес API без ключа доступа.
