# UI/UX v0.1 — структура на согласование

Русский desktop UI: светлый фон, белые таблицы, синие действия, янтарные предупреждения, текстовые статусы. Одна основная кнопка на этапе. Макет не использует внешние шрифты, CDN или ИИ-изображения.

## Навигация

Слева: Карточки, Черновики, Импорт Excel, Партии, Шаблоны. Администрирование появляется только в режиме просмотра администратора. Переключатель роли существует исключительно для обзора прототипа. В продукте права проверяются серверной сессией.

## Реестр

Сводка, вкладки статусов, поиск PN/GTIN/названия, фильтры ТН ВЭД/ответственного, sticky PN и заголовок. 12 строк на странице; выбранные ID сохраняются между страницами и фильтрами. Панель выбора показывает точное число, массовые действия, остановку и снятие выбора. Отправка открывает обзор, но заблокирована до подтверждения интеграции. Готовность полей, статус НК и локальная проблема показаны отдельно.

В прототипе сортировка PN, базовые фильтры и выбор выполняются локально. В продукте добавить расширенные фильтры категории/типа/партии/наличия шаблона, настройки колонок, серверную пагинацию, сохранение профиля и подтверждение выбора всех результатов отдельно от страницы.

## Карточка

Правая панель занимает 43% desktop; на узком экране — весь экран. Полноэкранный режим, вкладки Основное / Характеристики / Проверки / История, закреплённые нижние действия. Закрытие/переход с изменениями требует подтверждения; сохранение меняет только память макета. Сетевую ошибку и конфликт можно включить через сценарии. Переход от ошибки к полю работает.

В продукте: реальные searchable справочники и schema-driven поля, отдельные версии опубликованная/черновая, сверка внешних ревизий. В прототипе переключение версии только объясняет процесс, не создаёт фиктивный черновик НК. PN/GTIN/мощность не переносятся шаблоном автоматически.

## Массовые сценарии

Шаблоны: preview «было → предлагается → применимо»; существующие значения сохраняются. Дубли: сравнение новой карточки и кандидата, текст причины, разрешённое продолжение, запись в память истории. Будущий агрегированный список должен хранить решения отдельно для каждого кандидата и ревизии: прототип показывает один пример пары для выбранной партии, полноценный разбор 20 кандидатов ещё не реализован.

Excel: Файл → Сопоставление → Проверка → Подтверждение. Сейчас встроенный демонстрационный набор без чтения файлов; показаны строковые идентификаторы, формулы как ошибка, разные результаты строк и отдельное получение GTIN. Выбор mapping пока иллюстрирует экран, настоящую нормализацию и схемы реализовать на сервере.

Партии: точные количества по разным состояниям, ошибка строки, ожидание подписанта, неизвестный исход без автоматического повтора. Остановка требует причину, локальный архив не меняет внешний статус. Возврат из архива после сверки НК и явного продолжения — следующий этап; в прототипе ещё нет действия восстановления.

## Проверяемые состояния

Кнопка «Сценарии проверки»: нормальный каталог, пустой, загрузка, потеря сети, 429, 500/unknown, конфликт ревизий, 401, 403. На карточках представлены отказ модерации, отсутствие шаблона, выключенный подписант и две версии. Это искусственные UI-состояния, не тест HTTP-адаптера.

Полная матрица будущего browser QA дополнительно включает реальный 422/400 с серверными field errors, смену статусов, две вкладки с конкурентным сохранением, 100 выбранных карточек, реальные справочники, dark theme при внедрении общей темы. Светлая тема — единственная в этом этапе.
